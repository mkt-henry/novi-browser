# No.VI browser operating guide

1. Run `novi-browser list`. Choose the profile matching the required login identity and site. One identity belongs in one profile; use `No1`, `No2`, etc. If absent, register a site with `novi-browser add No1 --site Work --check https://work.example/account --signed-out /login --user user@example.com`. Never combine different login users in a profile. Choose reliable signed-out URL markers or `--signed-in-text`.
2. Set `NOVI_BROWSER_SESSION` to a stable identifier for your task when your tools launch independent parent processes. Successive calls share a tab and variables; independent sessions get separate tabs. The default uses the parent process identity. Browsers start on demand, default to headless, and close after five idle minutes with login cookies saved. Variables disappear when a worker closes.
3. Either hand off a complete trusted task with `novi-browser agent No1 --site Work "task, completion criteria, evidence to return"`, or control it directly with `novi-browser exec No1 --site Work -c "snap()"`. Agent mode requires Claude Code; its model defaults to `sonnet` and can be changed with `--model` or `NOVI_BROWSER_AGENT_MODEL`. It uses Bash only and skips permission prompts, so constrain the task. Resume using the returned `--resume` session. Verify delegated results.
4. Read `snap()` and act using its current refs: `click('e12')`, `fill('e12', value)`, `press('Enter')`, `select('e12', value)`. Never invent a ref. Use `snap(interactive=True)`, `snap(selector='[role="dialog"]')`, or `snap(ref='e12')` to narrow the view. Action helpers settle the page and return changed lines; avoid fixed waits and waiting on hidden selectors. If a ref is stale or hidden, read the returned changes or take another snapshot.
5. Helpers include `goto(url)`, `text(selector)`, `diff()`, `shot('result.png')`, `pages()`, `use(index)`, `sites()`, `secret(name)`, `check(site)`, `login(site)`, `human_click(locator)` and `human_type(text)`. Use `page.set_input_files` for uploads. Python variables persist between exec calls in the session, and the final expression is printed. `page` and `ctx` are Playwright objects. Exec has full local privileges. Never print secrets.
6. Before an **explicitly authorized** irreversible click (posting, sending, deleting, purchasing, final submission), record `key = fingerprint(identity, content, specific_action)` and `intent(key, 'description', site='Work')`. The site's login check must have passed. Click only within the user's authorization; inspect confirmation and call `done(key, page.url)`. If the response is lost, never repeat blindly. Inspect the site, then use `novi-browser resolve No1 --key KEY --state done|failed`. Only mark failed after establishing the action did not happen. The ledger does not intercept raw Playwright calls; follow this protocol yourself.
7. For expired login, try `novi-browser login No1 --site Work` once if a saved method exists. For human login, captchas or device verification, run `novi-browser open No1 --site Work --headed --note "Sign in and complete verification"`. Let the human finish, then run `novi-browser check No1 --site Work`. A visible window opens locally; sharing happens only through a configured `NOVI_BROWSER_SHARE_CMD`. Do not assume anyone was notified. A site registered with `--window` always opens headed.
8. Read the local site notes printed on the first open/exec. Save reusable discoveries with `novi-browser remember No1 --site Work "note"`. Search with `novi-browser memory --search "query"`, or read `memory No1 --site Work`. Notes are local and shared by site; keep secrets and confidential identity-specific details out of them.
9. Leave a task tab available for follow-up, or release your tabs with `novi-browser close --session YOUR_SESSION`. `close No1` closes the shared profile for every caller. On resource/busy errors (75/73), wait for other work or close unused profiles before retrying. Report blockers after a reasonable retry. Exit 77 means login expired; 78 means unknown profile/site; 69 means a missing dependency or unreachable configured remote machine.

The data home is `~/.novi-browser/` or `NOVI_BROWSER_HOME`. It contains live logins and must remain private. `secret(name)` reads `NOVI_BROWSER_SECRET_<NORMALIZED_NAME>`, then optional OS keyring (service `novi-browser`), then local `secrets.json`. Restart a worker after changing its environment secrets.

With `NOVI_BROWSER_REMOTE=user@host`, the same CLI runs through SSH on that machine. Send an upload with `--put path`; refer to its filename in remote code. New screenshots and other small top-level files return to the current folder and can replace same-named files. Without that variable every platform runs locally. No private server is needed. MCP clients can use `novi-browser-mcp` with list_profiles/add_site/open/exec/snap/close/remember/memory.

Return a concise result, observed evidence or screenshot path, and any remaining blocker. Never claim a submission or login succeeded without checking.
